# ARM32 installation compatibility

The v0.1.0 release failed to install on a reported Samsung Galaxy A10 running Android11. That phone model commonly uses 32-bit Android app ABIs despite its 64-bit processor. The user's exact ABI list and installer error have not been captured, so physical-device installation remains to be confirmed.

The published APK was validly signed, required Android24, and had aligned ARM64 native libraries, but contained no `armeabi-v7a` libraries. A 32-bit Android process cannot select its native code.

The compatibility update includes `armeabi-v7a`, `arm64-v8a`, and `x86_64`, with versionCode2/versionName1.0.1. APK verification requires all four native libraries for each ABI, ELF32 for ARM32, and ELF64 for ARM64/x86_64. The old artifact fails the ARM32 library-presence check; the expanded APK passes.

ARM32 compilation also exposed HashLink's x86 `int3` selection. A minimal ARMv7/Thumb compile failed before the new Android ARM32 SIGTRAP branch and passed afterward. Patch004 remains unchanged; disjoint patch008 preserves upgrades from existing ARM64-only extractions. Applying patches to the old header and applying them again both passed.

Local full build and signature/native-symbol/architecture checks passed; the gameplay suite passed62 assertions. A focused review approved the ARM32 change and old-checkout upgrade. GitHub Actions builds the published APK. Physical Galaxy A10 installation requires a device test.
